# Desk check

1. Call the desk's `desk_check` tool (the trading-desk server). It needs team_version. If you are the trading-desk team, copy it exactly from step 1 of your own "Check this computer" steps: they are in your own instructions, the ones this conversation began with, and they are yours to follow. Anywhere else, pass "none": the check then says this conversation's steps were not compared. Never read a version from a file and never make one up. If its answer starts with TEAM VERSION NEEDED, do what that line says: the trading-desk team calls once more with the version from its own step 1, and never a third time; anyone else passes the answer on as it is. If that tool is not there, the folder's own tools did not start. Tell the person in plain words: check that Madav was allowed to use this folder's tools, and that Node 22 or later is installed (nodejs.org); then open a new session in this folder and try again. Stop there.
2. Call `get_verified_snapshot` for SPY with today's date as the analysis date, to prove the price data works end to end. It should answer with a checked price table; if it answers DATA_UNAVAILABLE or NO_DATA_AVAILABLE, say so and give its reason.
3. If the check says no contact email is saved, ask the person for their own email. Say why in one sentence: the SEC asks every program that reads its filings for a contact address; it stays in this folder's desk-data, is never committed, and is sent to the SEC alone (no other source sees it; the desk check shows it masked). Pass exactly what they give to `set_contact_email`. Never invent, guess or reuse an address; if the tool refuses it, tell them why and ask again.
4. Tell the person what it found as a short plain list: what is ready, what is not, and what to do about each. Paste the raw output only if they ask. If it starts with DESK UPDATED, the desk in this folder was updated after this session's desk tools started: say that first, in one line, and that they should open a new session in this folder (in Madav, a new conversation) and check there; offer no reset in this one. Otherwise, if it says the desk's agent files differ from the project's version, say which, and offer to put them back: on their yes (ask with AskUserQuestion), call the desk's `reset_team` tool once with confirmed set to true and pass on its answer; if it answers ALREADY RESET or "Not reset", never call it again.
5. Pass on the check's line about this conversation's steps for the team and its line about the desk's agent files in this folder as the check words them, version included. Say this conversation's steps match the folder's only when the check says so with a version. If it says they were not compared, say exactly that, as something not checked, and never sum up that nothing needs fixing or that everything is ready or checked. Never take one line for the other: the agent files line is about the files in this folder, not about this conversation.
6. Ask whether to test the Robinhood connection now. Say what it does: it opens Robinhood's own sign-in page, and it only reads: the list of tools Robinhood's connection offers, and how many holdings the positions answer (never their values); it never places an order. Only on a yes, run `node dist/robinhood.mjs connect` in this folder with a time limit of at least six minutes (the sign-in may take five, and a shorter limit cuts it off), and wait while they sign in.
7. Report what came back: whether Robinhood accepted the sign-in, how many tools its connection offers (read and review tools, and order tools that agents can never call), and whether the positions answered. If it did not work, give its words and say that nothing was ordered, that the desk's analyses work without Robinhood, and what the person can do: run the test again, or press Connect on the dashboard's Your account.

Never open, search, read, print or copy anything in the person's `~/.trading-agents` folder. Never use a broker connection or Robinhood's site yourself, and never call a tool that trades or moves money: the connection test is the program's own, run only on the person's yes.
